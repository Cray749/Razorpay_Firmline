# Firmline — 5-minute demo video script

Timings are targets, not hard cuts — pace to what's on screen. All numbers below are the real, reproducible output of `npm run seed && npm run dev` → "Run the batch" against `seed-v1` (see [`PROGRESS.md`](PROGRESS.md) and the README's "What we measured" table). Re-verify with `npm run verify:checklist` before recording, in case the seed or code has changed since this was written.

| Time | Content | Notes for the presenter |
|---|---|---|
| 0:00–0:30 | **The problem, one sentence, one concrete number.** "India's RBI banned contacting recovery customers outside 8 AM–7 PM in 2026, and NPCI restricts when UPI AutoPay retries can even run. Most recovery bots don't know either rule exists." | Show the RBI/NPCI lines from the README's "Why now" section on screen as text, not just narration. |
| 0:30–1:15 | **What Firmline is, in plain language.** "Firmline looks at a batch of failed payments, abandoned checkouts, and overdue invoices, works out why, and tries to recover the money — but only in ways that are actually allowed. A deterministic compliance gate — plain code, not a prompt — sits between deciding and doing." | Show the architecture diagram from `docs/architecture.md` for ~5 seconds. |
| 1:15–2:30 | **Live batch run.** Land on `/`, click "Run the batch." Let it process the real 200-record `seed-v1` batch. Point out the live stamp animation landing on each case as it clears or blocks. Call out the summary tiles: 200 cases, ~82 cleared, ~118 blocked/rescheduled, 9 needing human review. | This is the single most important 75 seconds — don't rush it. Let at least 10–15 stamps visibly land before cutting. |
| 2:30–3:15 | **One case's full audit trail, read top to bottom.** Open `/case/b2b_0001` — this is the deliberate Rule-9 demonstration case: a naive "URGENT... FINAL NOTICE... Legal action will be taken..." message gets generated, then caught and blocked by the tone/content rule before it ever reaches the customer, and logged to the human review queue. Read 2–3 audit-trail lines aloud in plain English. | This case is chosen because it's the clearest "the compliance layer actually did something" moment — a real blocked message, not just a rule name in a table. |
| 3:15–4:00 | **Counterfactual view.** Open `/counterfactual`. Point out the headline number (112 of 200 cases diverge) and scroll to the same `b2b_0001` case: left column shows what a naive agent with no gate would have sent, right column shows Firmline's actual (blocked) outcome, side by side. | This view is what the README calls "the single most convincing few seconds of the demo" — don't skip it even if time is tight elsewhere. |
| 4:00–4:40 | **Dashboard — real numbers.** Open `/dashboard`. Call out: ₹2.18 crore total revenue at risk, ₹48.97 lakh gross recovered (modeled, clearly labeled as such), ₹48.8 lakh net recovered yield in gold, 22.41% recovery rate, and the compliance rule fire chart — all 12 rules firing, shown as a working safeguard, not hidden. | Emphasize the "modeled outcome on synthetic data" disclaimer text is on screen — this is a credibility point, not a hedge. |
| 4:40–5:00 | **What's built vs. what's next, live link on screen.** "Everything here is real, tested, and reproducible — diagnosis accuracy, rule fire counts, the counterfactual comparison. What's not live yet: real Gemini and Razorpay credentials in this deployment, and pre-rendered Hinglish voice. Link's on screen." | Show the deployed URL text card for the last 3 seconds, not just spoken. |
